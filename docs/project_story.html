01. Проблема и подход

Контраст: Агент в одиночку vs Агент под управлением AutoHarness

Современные LLM-агенты при решении инженерных задач часто страдают от галлюцинации завершенности, подставляя заглушки и одобряя собственный непроверенный код.

Стандартный агент без обвязки Тот же агент под управлением AutoHarness
Пишет по памяти: придумывает схемы API, форматы ответов и сигнатуры функций, не заглядывая в первоисточник. Сверяет с оригиналом: шаг evidence add --kind reference требует реальный JSON, сэмпл данных или эталонный тест до первой строчки кода.
Имитация работы (Fake Stubs): маскирует недоделки заглушками (pass, return True, assert True). AST Anti-Shim Sentinel: бестокеновый анализатор синтаксического дерева блокирует пустые заглушки и фиктивные тесты на этапе проверки diff.
Сам себе судья: агент пишет код и сам же выносит решение о завершении задачи (неустранимый конфликт интересов). Независимый критик: изолированный субагент с одноразовым токеном ANSWER-ID сверяет каждый пункт контракта (B1, B2, B3).
Зацикливание на ошибках: агент бесконечно повторяет один и тот же неработающий паттерн правки. Принудительная смена подхода: после 3 неудачных раундов CLI требует сменить парадигму (от догадок к документации, от патча к полному рефакторингу).
Утечка контекста и потеря кэша: перегружает диалог длинными логами, сбивая KV-кэш LLM и вызывая рост затрат на токены в 4–8 раз. AP-5 Anchor Tier & Skim: замораживает системный промпт для 100% сохранения KV-кэша, а логи тестов каскадно сжимает до сути трейсов.
02. Инженерные компоненты

Ключевые внедрения и их прикладная ценность

Архитектура спроектирована на основе SOTA-исследований Google Research (Harness², Nomos, Skim) без сторонних тяжелых библиотек.

AST Anti-Shim & Anti-Hollow Sentinel (Синтаксический сторож заглушек и пустых тестов)

Качество кода

Синтаксический анализ абстрактного дерева (Python ast, Tree-sitter) без расхода LLM-токенов. Выявляет EMPTY_STUB_BODY, TRIVIAL_RETURN_STUB, нереализованные методы (raise NotImplementedError) и тесты-пустышки (assert True, hollow_check).

Практическая польза: Гарантирует, что агент реально реализовал логику, а не сымитировал прохождение тестов фиктивными заглушками.

AP-5 Anchor Tier & Session Compactor (Якорный кэш промпта и сжатие контекста)

Экономика токенов

Трехуровневая модель сжатия контекста: Anchor Tier (шаг 0 со строгим сохранением префикса для кэша Anthropic/Gemini/OpenAI), Distill Tier (сжатые логи промежуточных шагов) и Epoch Tier (обобщенные вехи завершенных задач).

Практическая польза: Снижение затрат на токены до 85% и ускорение выдачи первого токена (TTFT) в 4–8 раз за счет стабильного попадания в KV-кэш провайдера.

Consequence Simulation & Blast Radius (Симуляция последствий и радиус взрыва)

Безопасность

Предварительное моделирование последствий команд перед одобрением человеком: расчет индекса риска (0–100), радиуса взрыва и класса обратимости (READ_ONLY, REVERSIBLE, HIGH_RISK, IRREVERSIBLE) с выдачей рецепта отката.

Практическая польза: Защита от случайного уничтожения продакшн-данных, поломки баз или разрушительных изменений файловой системы.

Cascading Output Compression (`skim`) (Каскадное адаптивное сжатие логов)

Контекстный бюджет

Адаптивный алгоритм сокращения вывода pytest, компиляторов и git diff на 70–95%. Отсекает повторяющийся шум пройденных тестов, изолируя точные координаты упавших ассертов, стектрейсы и локальные переменные.

Практическая польза: Предотвращает переполнение контекста агента простынями логов, удерживая в фокусе только релевантную причину сбоя.

Regression Sentinel & Rollback Guard (Сторож регрессий и автоматический откат)

Надежность

Самоконтролируемый сторож: фиксация снапшотов эталонного состояния репозитория и мгновенный автоматический откат (через git restore и git clean), если новая итерация ломает тесты или вносит регрессии.

Практическая польза: Позволяет безопасно запускать автономный цикл разбора бэклога (autoharness drive) без риска деградации кодовой базы.

Swarm DAG & Role Isolation (Мультиагентный граф задач и изоляция ролей)

Мультиагентность

Топологическая оркестрация графов задач на graphlib.TopologicalSorter с контрактными барьерами: жесткое разделение обязанностей (Researcher, Coder, Verifier, Critic) и запрет на продолжение до сдачи артефактов.

Практическая польза: Исключает каскадное распространение галлюцинаций и ошибок между взаимодействующими субагентами.
03. Архитектура системы

8-слотовая каноническая модель обвязки агента

Вдохновлена Google Research Harness² (arXiv:2610.14224). Каждая область конфигурации агента вынесена в отдельный слот с версионированием и диффом.

Slot 01
System Prompt (Системный промпт / Роль)
Ролевые инварианты, правила поведения и неизменяемый базовый контекст.
Slot 02
Guardrails (Защитные барьеры)
Ограничения прав, скоринг безопасности плагинов и политики выполнения.
Slot 03
Memory (Долгосрочная память)
SQLite FTS5 + LEANN Vector с гибридным поиском и аудитом согласованности.
Slot 04
Skills (Каталог навыков)
Библиотека внешних инженерных знаний и проверенных практик (markdown).
Slot 05
Tool Guidance (Инструкции к инструментам)
Сжатые сигнатуры инструментов в TypeScript .d.ts для Code Mode.
Slot 06
Scripts (Исполняемые скрипты)
Исполняемые скрипты верификации и тестов внутри изолированной песочницы.
Slot 07
Subagents (Топология субагентов)
Роли субагентов (независимый критик, ревьюер кода, арбитр споров).
Slot 08
Middleware (Слой перехвата / Хуки)
MCP Gateway, маскирование секретов в логах и перехватчик вызовов (hooks).
04. Практический кейс: Банковский клиент

Полный цикл работы на примере E2E-тестирования интернет-банка

Задача: «Покрыть E2E автотестами критический путь клиента интернет-банка: вход по 2FA (OTP/SMS), просмотр баланса счетов, P2P-перевод по номеру телефона с защитой от двойного списания (Double Submit / Idempotency) и проверка истории операций».

АРХИТЕКТУРНЫЙ ГРАФ ИСПОЛНЕНИЯ (WORKFLOW DAG & GUARDRAILS)
Инженерная траектория задачи: от контракта до независимого аудита и базы знаний
Полный цикл AutoHarness
Прямой конвейер: строго типизированный поток артефактов
Сторожа и барьеры: Pre-Tool, AST Anti-Shim, Consequence Sim
Петля обратной связи: откат и смена техники при тупике
Финализация: запись в SQLite FTS5 и эталонный снапшот
ШАГ 1. INIT & СКОРИНГ ДОВЕРИЯ (ФИЧА: Capability-Raising & Trust Scan — Поднятие режима и скан доверия)
Анализ финтех-рисков
Как раскрывается фича: Детектор возможностей видит в задаче финансовые транзакции, браузер и API — режим автоматически повышается с light до reviewed (обязателен независимый критик). Каталожный сканер проверяет плагины на рейтинг доверия (Trust Score) и отсутствие скрытых сетевых утечек.
autoharness init "E2E тесты банковского клиента: 2FA, баланс, P2P перевод с идемпотентностью" --mode reviewed
autoharness search skill "banking e2e security idempotency"
ШАГ 2. СНЯТИЕ ДАМПА DOM & МАСКИРОВАНИЕ ДАННЫХ (ФИЧА: Secret Redaction & Pre-Tool Hook — Маскирование секретов и блокировка правок)
Замер оригинала & Безопасность
Как раскрывается фича: Агент подключается к тестовому стенду интернет-банка и замеряет реальные селекторы (data-testid="phone-input", маска суммы перевода, окно OTP-кода). Встроенный щит Dynamic Secret Redaction автоматически маскирует номера тестовых карт (4111********1111) и токены авторизации (Bearer eyJhb...[REDACTED]), исключая их утечку в логи и контекст модели.
autoharness evidence add bank-dom-snapshot.json --kind reference
autoharness evidence add bank-selectors.json --kind facts
autoharness brief --goal "B1: 2FA вход; B2: P2P перевод с проверкой лимита; B3: защита от double-submit" \
  --techniques "idempotent-transfer: unique uuid header; reactive-locators: expect().toBeVisible(); clean-fixtures: isolated accounts" \
  --verify "npx playwright test" --constraints "маскирование секретов, никаких sleep(5000)"
✒️ Флаг --techniques (Принцип каллиграфии): Декларирует обязательные инженерные техники ремесла. Критик автоматически получит инструкцию: любое отклонение от задекларированных техник или попытка вставить любительский костыль считается major difference.
🛡️ Pre-Tool Hook: Инструменты записи и запуска кода заблокированы до момента фиксации контракта в журнале.
ШАГ 3. СИНТАКСИЧЕСКИЙ КОНТРОЛЬ ТЕСТОВ (ФИЧА: AST Anti-Shim Sentinel — Сторож пустых заглушек)
Бестокеновый надзор
Как раскрывается фича: Агент пишет Page Objects (BankLoginPage, TransferPage, AccountsPage). При попытке записать diff запускается синтаксический анализатор абстрактного дерева (AST):
⛔ Блокировка фиктивного кода: Если агент оставил пустой метод async submitTransfer() { /* pass */ } или написал тест-пустышку без реальной проверки списания баланса (expect(true).toBe(true)) — фиксация блокируется с кодом TRIVIAL_ASSERTION_CHEAT.
Модель вынуждена написать реальные ассерты: проверку изменения баланса счёта отправителя и получателя, проверку статуса транзакции и списание комиссии.
ШАГ 4. СИМУЛЯЦИЯ ПОСЛЕДСТВИЙ (ФИЧА: Consequence Simulation & Blast Radius — Оценка рисков и радиуса взрыва)
Защита от сбоя стенда
Как раскрывается фича: Для тестирования сценария с нулевым балансом агент пытается сбросить состояние тестовых аккаунтов вызовом опасного API: POST /api/v1/test/reset-accounts. AutoHarness перехватывает вызов:
⚠️ Расчет радиуса взрыва (arXiv:2610.40753): Risk Score: 85/100, класс: HIGH_RISK. Система вычисляет затронутые сущности (12 счетов, история транзакций) и требует прямого подтверждения человека с показом инструкций по откату (Rollback Guidance).
ШАГ 5. ЗАПУСК ТЕСТОВ & СЖАТИЕ ЛОГОВ (ФИЧА: Verify Run + Skim + AP-5 KV-Cache — Запуск тестов, сжатие логов и кэш)
Экономия бюджета 85%
Как раскрывается фича: AutoHarness выполняет прогон E2E-сьюта. Логи браузера (WebSocket-сообщения обновления баланса, сетевые ответы банковского шлюза) занимают 6000+ строк.
autoharness verify run "npx playwright test --project=chromium" --for B2
• Cascading Skim: Сжимает 6000 строк до 35 строк сути (отсекает 98% шума, оставляя только стектрейс ошибки валидации маски ввода суммы).
• AP-5 Anchor Tier: Шаг 0 (банковские правила и промпт) сохраняется неизменным, гарантируя 100% попадание в KV-кэш провайдера (Gemini/Claude).
ШАГ 6. НЕЗАВИСИМЫЙ КРИТИК (ФИЧА: Critic Subagent & Role Isolation — Субагент-критик и изоляция ролей)
Аудит финансовой логики
Как раскрывается фича: Запускается отдельный изолированный субагент-критик с одноразовым криптографическим ANSWER-ID. Критик не писал этот код, у него нет «авторской предвзятости». Он руководствуется принципом: слова автора в комментариях и коммитах — это unverified self-report, они игнорируются.
🔍 Как критик понимает, что идемпотентность (Double Click) реально протестирована, а не сфальсифицирована?
Критик не «верит» агенту, а проверяет три независимых слоя доказательств:
1. Анализ исходного кода теста в diff (Синтаксис действия)
Критик проверяет, есть ли в коде физическая симуляция конкурентного нажатия кнопки «Перевести», а не просто одиночный клик: 
// Критик ищет конкурентные вызовы в коде теста:
await Promise.all([
  transferButton.click(),
  transferButton.click() // повторный быстрый клик
]);
await expect(transferButton).toBeDisabled(); // кнопка заблокирована в UI
2. Проверка перехвата сетевого слоя (Network Interception & Assertions)
Критик проверяет, перехватывает ли тест исходящие HTTP-запросы и валидирует ли бизнес-инварианты защиты от двойного списания: 
// Критик проверяет наличие ассертов на idempotency-key и счетчик запросов:
expect(requests.length).toBe(1); // отправлен ровно один запрос, второй отсечен UI
expect(requests[0].headers()['x-idempotency-key']).toBeDefined(); // есть UUID-ключ
expect(await accountsPage.getBalance()).toBe(initialBalance - transferAmount); // баланс списан один раз
3. Проверка лога реального запуска (runs/*.log) & Защита от обмана (AST Anti-Hollow)
• Сверка лога выполнения: Критик открывает лог runs/01-playwright.log и убеждается, что тест should prevent double submit реально выполнился раннером и завершился с кодом 0, а не был пропущен (.skip()).
• AST Anti-Hollow Sentinel: Если агент схитрил и написал пустой тест с фальшивой проверкой expect(true).toBe(true), синтаксический сторож помечает результат как TRIVIAL_ASSERTION_CHEAT, и критик выносит вердикт VERDICT: blocker.
Реакция критика на разные варианты реализации:
Агент кликнул 1 раз и проверил надпись «Успешно» ❌ B3: missing (повторный клик не тестировался) $\to$ VERDICT: major
Агент кликнул 2 раза, но поставил waitForTimeout(5000) и пустой ассерт ❌ B3: contradicts (обнаружен flaky-таймаут и фиктивный тест) $\to$ VERDICT: major
Клик через Promise.all, перехват сети, проверка x-idempotency-key и баланса ✅ B3: met, ACCEPT: yes $\to$ задача завершена
🛡️ Итог: Пока в diff нет физического кода перехвата запросов, а в логе нет факта успешного выполнения — критик не пропустит сдачу задачи.
ШАГ 7. СТОРОЖ РЕГРЕССИЙ & БАЗА ЗНАНИЙ (ФИЧА: Sentinel & Memory Reconciliation — Сторож регрессий и аудит памяти)
Защита от регрессий & Опыт
Как раскрывается фича: После вердикта ACCEPT: yes сторож регрессий (Regression Sentinel) создает снимок эталонного состояния. В базу знаний SQLite FTS5 сохраняется выученный урок по специфике банковского UI:
autoharness lesson add "В банковском UI маска ввода номера телефона (+7 (999) ...) форматирует значение с задержкой 50мс: использовать page.locator().fill() с проверкой значения поля вместо последовательного type()."
autoharness teardown --save-recipe bank-e2e-transfer-suite
05. Расширенные возможности

Что еще есть в арсенале AutoHarness: За рамками базового кейса

Комплекс исследовательских модулей для автономной работы, мультиагентной координации и глубокого статического анализа кода.

AST Call Graph & Impact Analysis (Граф вызовов AST и анализ зоны поражения)

codemap --impact

Парсинг абстрактного дерева вызовов без LLM. Перед правкой метода система рассчитывает транзитивную зону поражения: «Правка метода X затронет 14 тестов, 3 файла фикстур и 2 контроллера», а также находит циклические зависимости (codemap --arch).

Практическая польза: Предотвращает слепые правки кода: агент точно знает, какие зависимые модули могут сломаться.

Multi-Agent Swarm DAG (Мультиагентный роевой граф задач)

autoharness swarm

Топологический граф задач на graphlib.TopologicalSorter с разделением ролей (Researcher, Coder, Verifier, Critic) и жесткими барьерами артефактов (Artifact Barriers): кодер не запустится, пока исследователь не сдал валидированный контракт.

Практическая польза: Исключает каскадное распространение галлюцинаций между взаимодействующими субагентами.

Continuous Autonomy Self-Driving (Беспилотный цикл непрерывного разбора бэклога)

autoharness drive

Беспилотный цикл непрерывного разбора бэклога задач (followups.json). Приоритетная очередь, контроль бюджета итераций, пред- и пост-проверка через Sentinel и автоматический откат при регрессиях без участия человека.

Практическая польза: Позволяет ставить агенту пачку задач на ночь: он решит всё, что может, не сломав кодовую базу.

Propose–Probe–Compose Loop (Контрастный цикл автосинтеза обвязки)

autoharness probe -k

Исследование Google Research Harness² (arXiv:2610.14224): параллельный запуск $K$ альтернативных конфигураций 8 слотов в песочницах, сопоставление траекторий ошибок и автосинтез выигрышной обвязки без разметки ground truth.

Практическая польза: Агент сам подбирает под задачу наилучший баланс строгости проверок, лимитов токенов и инструментов.

Code Mode & .d.ts Generation (Песочница Code Mode и генерация типов TypeScript)

harness_execute

Изолированная Node.js песочница для выполнения пакетов вызовов инструментов в один шаг. Сжатие тысяч токенов JSON-схем в ультракомпактные TypeScript-типы (.d.ts) экономит до 90% токенов на понимание интерфейсов.

Практическая польза: Замена 20 отдельных медленных вызовов инструментов одним быстрым скриптом с локальным циклом.

Geometric Stencil Scanner (Геометрический сканер штампов и контуров)

autoharness stencil

Извлечение контуров и якорных координат из дизайн-макетов (Figma, PNG) в геометрические векторные штампы для математически точного контроля верстки и позиций интерфейса (pixel-to-pixel).

Практическая польза: Объективная проверка визуального соответствия макету без размытых субъективных оценок.

Memory Drift Reconciliation (Устранение рассогласований и аудит памяти)

memory reconcile

Аудит персистентной базы SQLite FTS5 против реального AST кодовой базы. При переименовании классов или смене архитектуры система находит устаревшие и противоречивые уроки и удаляет сирот внутри атомарного SAVEPOINT.

Практическая польза: Память проекта не деградирует со временем и всегда отражает актуальное состояние кода.

Precedent Rulings & Arbiter (Прецедентные решения и арбитраж споров)

autoharness ruling

Разрешение споров между агентом и критиком через независимого арбитра. Принятое решение человека или арбитра фиксируется в судебный прецедент (ruling), и будущие критики больше не имеют права спорить по этому поводу.

Практическая польза: Исключает повторные тупики по вопросам, которые команда проекта уже однажды решила.
06. Справочник команд

Полный арсенал команд AutoHarness CLI

Вся функциональность CLI структурирована по 8 функциональным подсистемам. Каждая команда выдает стандартизированный JSON с полем next.

Группа и Команды Назначение и Описание Пример вызова
1. Жизненный цикл задачи
init, brief, mode, status, claim, waive, teardown 		Инициализация изолированной задачи, контрактный бриф (цели B1-B3, замеры фактов, ограничения и профессиональные техники --techniques с принципом каллиграфии), повышение режима (light $\to$ full $\to$ reviewed), смена сессии (claim) и финализация (teardown). autoharness init "..." --mode reviewed
autoharness brief --goal "..." --techniques "idempotent-transfer: ...; reactive-locators: ..."
autoharness teardown --save-recipe
2. Первоисточники и тесты
evidence, verify, skim, sentinel 		Регистрация первоисточника (reference), замер фактов (facts), фиксация диффа с защитой Anti-Shim, запуск верификационных команд (verify run), каскадное сжатие логов (skim) и сторож регрессий (sentinel). autoharness evidence add file --kind facts
autoharness verify run "pytest -q" --for B1
autoharness sentinel snapshot
3. Независимый аудит
critic, review, approach, arbiter, ruling 		Генерация задания независимому критику с одноразовым ANSWER-ID, фиксация раундов ревью, принудительная смена техники реализации при 3 ошибках подряд (approach --now <technique>), арбитраж тупиков и регистрация судебных прецедентов. autoharness critic
autoharness approach --part "transfer" --now "atomic-upsert"
autoharness review --by critic --answer-file f
4. Интеллект кода (AST)
codemap 		Синтаксический индекс классов, методов, сигнатур без токенов LLM. Построение графов вызовов (callers/callees), расчет зоны поражения правок (--impact), поиск циклических зависимостей (--arch) и проверка заглушек (--check-shims). autoharness codemap src/ --impact MyService
autoharness codemap src/ --arch
autoharness codemap tests/ --check-shims
5. Мультиагентность & Драйв
swarm, drive, followup 		Планирование и выполнение графа задач (DAG) на TopologicalSorter с барьерами артефактов и изоляцией 4 ролей. Беспилотный цикл разбора бэклога задач (drive) с контролем бюджета и автооткатом. autoharness swarm run plan.json
autoharness drive --budget 10
autoharness followup add "..."
6. Исследования Harness²
slot, probe, compact, stencil 		Инспекция, экспорт и версионируемый дифф 8 слотов обвязки агента (slot). Контрастный авто-синтез обвязки в песочницах (probe). 3-уровневое сжатие контекста диалога с фиксацией AP-5 кэша (compact). Геометрический сканер контуров (stencil). autoharness slot diff --target prev.json
autoharness probe -k 2
autoharness compact run --keep-last 5
autoharness stencil scan mockup.png
7. Безопасность и Шлюз
simulate, permissions, gateway, inspect, vet 		Симуляция последствий команд с расчетом Risk Score и радиуса взрыва (simulate). Управление режимом авто-подтверждений (permissions/yolo). MCP-шлюз с горячим добавлением серверов и Node.js песочницей Code Mode. Скоринг доверия плагинов (inspect). autoharness simulate "rm -rf dist"
autoharness gateway approve
autoharness inspect mcp server-name
8. Память и Навыки
memory, lesson, skill, recipe, eval, journal 		Гибридный поиск (SQLite FTS5 BM25 + LEANN Vector) и аудит памяти против AST (memory reconcile). Накопление уроков от трения (lesson). Локальная библиотека навыков и слепое A/B-тестирование (skill test). Сохранение рецептов окружений (recipe). Замер метрик качества (eval) и авто-ведение JOURNAL.md. autoharness memory reconcile --prune-orphans
autoharness skill test my-skill
autoharness eval compare baseline target
autoharness journal

  • LEANN Vector Search: векторный поиск чисто на стандартной библиотеке Python без зависимостей.

  • AP-5 Anchor Tier & Skim: сохранение KV-кэша LLM и сжатие логов тестов на 70–95%.
  • Декомпозиция монолита: модульное разделение ядра CLI на cli, hooks, subsystems и meta.

Стабилизация подпроцессов и тестовой инфраструктуры

  • Точные пути Python: замена системных алиасов python на sys.executable во всех подпроцессах.
