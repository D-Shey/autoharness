Где проект прокачан на максимум (Superpowers)
1. Инженерная дисциплина и Zero-Trust Protocol init / brief / verify / mode

Агенты по природе спешат и генерируют код по памяти. AutoHarness принудительно останавливает агента: требует собрать пруфы (`evidence`), зафиксировать бриф до первой строчки кода и верифицировать результат реальным выполнением тестов, исключая иллюзию завершенности («галлюцинацию успеха»).

✓ Исключает слепые коммиты и непроверенные изменения.
2. Code Mode и изолированная V8-песочница sandbox.py / codegen.py

Революционный переход от пошаговых native tool calls к пакетному исполнению типизированного TypeScript-кода. Скрипт в изоляте `node:vm` делает циклы, агрегацию и фильтрацию данных, обращаясь к MCP-инструментам через RPC. Секреты отсекаются через `child_env`, а зависания блокируются двойным сторожевым таймером.

✓ Сокращение расхода контекста на 80–95%, защита API-ключей.
3. Динамический Gateway без перезапуска агентов gateway.py / mcp_client.py

Обычные кодинг-агенты требуют перезапуска при добавлении новых MCP-серверов. Gateway выступает единым прокси-сервером, поддерживающим горячее добавление, одобрение разрешений и мгновенную компиляцию JSON Schema в ambient `.d.ts` типы для LLM.

✓ Zero-restart MCP интеграция, работа по stdio и HTTP.
4. Независимый критик и протокол эскалации critic.py / approach.py / arbiter.py

Архитектурный запрет самопроверки («Don't judge your own work»). На этапе ревью поднимается отдельный субагент-критик без предвзятости исполнителя. При повторных сбоях система заставляет сменить подход (`approach`), а затем передает вердикт независимому арбитру.

✓ Разрыв циклов застревания на одной и той же ошибке.
5. Кросс-агентная поддержка и Zero-Dependencies agents.py / trust.py

Поддержка 9 основных сред (Claude Code, Codex, Gemini, Qwen, GigaCode, Strands, Antigravity, Cursor, Kimi). Проект написан на чистом стандартном Python без внешних зависимостей в рантайме, что гарантирует работу на любой машине без конфликтов виртуальных окружений.

✓ Абсолютная переносимость (Linux, macOS, Windows).
⚠️
В чём пробелы и белые пятна (Strategic Gaps)
1. Отсутствие семантической памяти (Graph RAG / Embeddings) Оценка: 45% (Критический пробел)

Вся долговременная память сейчас держится на текстовых файлах (`rulings.json`, `followups.json`, `events.jsonl`) и поиске по регуляркам/подстрокам. Нет векторных эмбеддингов, семантического индекса кодовой базы (Code Property Graph / AST Graph) и ассоциативного извлечения релевантного опыта прошлых задач.

⚡ Точка роста: Внедрение локального векторного поиска (например, SQLite-vec / Chroma) без нарушения zero-dependency ядра.
2. Отсутствие командной роевой оркестрации (Swarm / Multi-Agent) Оценка: 50% (Значительный пробел)

AutoHarness управляет взаимодействием «один агент + независимый критик на проверку». Нет архитектуры для параллельной работы роя специализированных агентов (Team Lead, Архитектор, Исследователь, Разработчик, QA-автоматизатор), одновременно решающих подзадачи одного эпика с синхронизацией общего состояния.

⚡ Точка роста: Поддержка протокола DAG-задач для параллельного запуска нескольких агентов под контролем харнеса.
3. Фоновая непрерывная автономность (24/7 Continuous Loop) Оценка: 60% (Умеренный пробел)

Текущая философия намеренно ориентирована на сессионный Human-in-the-loop контроль (агент останавливается и ждет одобрения опасных действий или завершения таска). Отсутствует режим автономного «ночного демона» (Nightly Self-Driving), который может автономно брать задачи из issue tracker, исправлять их и формировать PR.

⚡ Точка роста: Реализация защищенного автономного раннера с жестким бюджетом токенов и лимитом попыток.
4. Отсутствие автоматических бенчмарков (SWE-bench Evals) Оценка: 62% (Умеренный пробел)

В проекте есть команда `autoharness eval`, но она предназначена для ручной фиксации результатов. Нет встроенного набора стандартных индустриальных бенчмарков (SWE-bench Lite, HumanEval, CyberSecEval) для автоматического замера: насколько внедрение AutoHarness статистически снижает процент регрессий и галлюцинаций моделей.

⚡ Точка роста: Встроенный CI-раннер для измерения pass@1 и регрессий на типовых реальных задачах.
5. Ограничение сред песочницы только Node.js Оценка: 70% (Минорный пробел)

Code Mode исполняется через встроенную песочницу `node:vm` на JavaScript/TypeScript. Если агент предпочитает писать скрипты агрегации на Python (Pyodide / WASM / RestrictedPython) или Bash, у него нет аналогичной безопасной песочницы для Python Code Mode.

⚡ Точка роста: Добавление легковесной Python/Wasm песочницы для агентов экосистемы Pydantic-AI / LangChain.
